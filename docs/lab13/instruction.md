# Инструкция для команды: PM-ассистент (ЛЗ 13)

## Что это

Еженедельный черновик статус-отчёта проекта для спонсора. Числа (коммиты, задачи, сборки) считает скрипт по GitHub API. Языковая модель только формулирует текст вокруг этих чисел. **Черновик не отправляется без проверки человеком.**

## Как пользоваться

1. Каждую пятницу после 16:00 откройте сайт → **Управление → PM-ассистент** (или запустите `python scripts/weekly_status.py`).
2. Укажите период (по умолчанию — прошедшие 7 дней) и нажмите «Собрать факты и сделать черновик».
3. Проверьте **каждое** утверждение черновика по GitHub (Issues, Actions, коммиты). Каждое утверждение запишите в «Журнал проверки» с вердиктом: верно / меняет смысл / стилистика.
4. Исправьте текст в поле «Итоговый текст» и нажмите «Сохранить: факты проверены мной».
5. Запишите время на проверку и правку в «Время на этот отчёт» — без этого не посчитать экономию.
6. Отправьте итоговый текст спонсору (скачать .md). Раскрытие использования ИИ должно остаться в тексте.

## Кто отвечает

| Роль | Что делает |
|---|---|
| Менеджер проекта | запускает, проверяет факты, отправляет отчёт; отвечает за содержание |
| Разработчик | поддерживает скрипт и промпт, меняет версию промпта после правок |
| Спонсор | получает только проверенный текст |

Черновик попадает в базу сайта (таблица `pm_reports`) и в папку `reports/` (если запуск скриптом). В GitHub Actions по пятницам собирается отчёт без ИИ — его можно скачать во вкладке Actions → weekly-status → Artifacts.

## Какие данные запрещено передавать модели

| Данные | Почему нельзя |
|---|---|
| Персональные данные владельцев и сотрудников (ФИО, телефоны, адреса, почта) | Закон РК о ПДн: обработка только с согласия и для заявленной цели; статус-отчёту они не нужны |
| Медицинские записи пациентов (диагнозы, жалобы) | Конфиденциальные данные клиники, не относятся к статусу проекта |
| Токены, пароли, ключи API, содержимое `.env` | Утечка даёт доступ к системам; модель может повторить их в тексте отчёта |
| Финансы клиники и договоры (выручка, цены поставщиков) | Коммерческая тайна заказчика |
| Тексты переписки с заказчиком и протоколы встреч | Могут содержать договорённости, которые модель выдаст за факт |
| Оценки производительности конкретных людей | Отчёт о проекте не должен превращаться в оценку сотрудника; модель может исказить вывод |

В скрипт передаются только агрегированные числа и заголовки закрытых задач. Количество авторов коммитов передаётся числом, без имён.

## Раскрытие использования ИИ (вставляется в каждый отчёт автоматически)

> Текст черновика сформулировала языковая модель qwen2.5:3b (локально, Ollama) по данным GitHub API; все числа посчитаны скриптом, модель их не вычисляла. Факты проверил(а): ФИО, дата.
